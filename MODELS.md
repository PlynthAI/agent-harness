# Current model selections

Source snapshot updated 14 October 2026 against the harness role files and
`claude/claude-map.json`. Installed bindings are compared separately after
deployment. Refresh this file when changing selections.

## Codex team lead

| Setting | Selection |
|---|---|
| Team lead model | Chosen per session in the Codex model picker |
| Suggested choice | GPT-6.1 Sol (`gpt-6.1-sol`) at `high` |
| Plan-mode reasoning effort | `xhigh` |
| Service tier | `default` |

The team lead's model is the operator's choice in the picker, and GPT-6.1 Sol
`high` is the suggestion the visual guide shows. The plan-mode effort and service tier are
saved settings in the user config (`~/.codex/config.toml`). Its
`model`, `model_reasoning_effort` and `model_provider` values are not the
team lead's model choice. Existing chats and explicit delegation overrides can use
different selections.

## Claude Code roles

Claude Code runs eight subagents, generated by
[claude/sync-claude.ps1](claude/sync-claude.ps1). Seven run Claude models.
reviewer is the one Codex-runtime forwarder: a Haiku agent with only Bash runs
the Codex reviewer role headlessly with `codex exec`; the run is kept as an
exec session for traces and stays out of the Codex app's default thread list.
Its model and effort come from the table above.
The alias `haiku` resolves to Claude Haiku 5.5 (`claude-haiku-5-5`, released
7 October 2026) in the desktop app as of 8 October 2026.

|---|---|---|---|---|

design, UI, frontend and taste work and harder implementation and
investigation at `high`; fast_worker, explorer and researcher use
Sonnet 5.5 `high`. The planner on Opus 5.5 `xhigh` stays the advisor. fast_review
reviews a bounded slice or candidate on Haiku 5.5 `xhigh`; tester runs
checks on Haiku 5.5 `xhigh`. reviewer takes the accountable integrated-candidate
review or a justified specialist scope. See [the forwarding contract](claude/README.md#codex-runtime-roles).

## Scope and overrides

- Operator selection, 30 September 2026: native Sol for implementation,
  review, exploration, research and testing; native Astra high for the planner's
  advice and plans.
- Operator selection, 7 October 2026: fast_worker and fast_review use
  DeepSeek V4.1 Flash through Codex Router at source effort `max`.
  smart_worker stays on native GPT-6.1 Sol and uses `xhigh`. The other four
  Sol roles stay at `high`, and planner stays on native Astra `high`.
  These are model selections, not a quality or cost comparison. Claude
  fast_review then forwarded read-only to Codex (superseded 8 October); reviewer keeps its writable
  Codex forwarder. The coordinator role is retired; ordinary chat mains own
  coordinate and orchestrate-work.
- Operator selection, 8 October 2026: Claude-side tester moves to Haiku 5.5
  `xhigh` and Claude-side fast_review becomes a native Claude role on Haiku 5.5
  `xhigh`; the Codex-side fast_review keeps DeepSeek. On the 2cdc991 baseline
  slice, Haiku 5.5 at its default effort found the setup-guide Serena and
  Postgres mismatch DeepSeek found, plus a live config drift, in about 2
  minutes against about 16.5. On the same slice, `high` took about 5
  minutes and returned 4 findings; `xhigh` took about 7 minutes and returned
  6, adding two real dangling links from tracked files into the git-ignored
  workspace, for a negligible token cost difference. fast_review therefore
  runs at `xhigh`. The reviewer forwarder moves from the plugin's companion
  to `codex exec`.
- Operator selection, 14 October 2026: Codex tester uses GPT-6 Luna `xhigh`;
  Claude fast_worker, explorer and researcher use pinned Sonnet 5.5 `high`.
  Other bindings are unchanged.
- Operator selection, 17 October 2026: Claude planner moves from Fable 5.1
  `high` to Opus 5.5 `xhigh`, for lower cost and more usage headroom; judged
  on the plans it writes. Codex planner stays on Astra `high`.
- Router picker options are not assignments; this snapshot covers the eight
  shared roles, not a connectivity test or every other tool's provider profile.
- This snapshot does not audit project overrides, establish every existing chat's effective model, or test provider connectivity.

Worker roles renamed and operator selections applied on 24 September 2026.
