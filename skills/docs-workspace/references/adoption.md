# Workspace adoption routing

For fresh or existing workspace adoption, use the source harness's
`harness-docs-starter/README.md`. That guide owns the preparation, project-owner brief,
refresh and preservation sequence; keep the procedure there rather than copying
it into installed skills. If the source is unavailable, report that adoption
reference gap. It does not block ordinary document writing.

For the current task, follow the workspace AGENTS.md and its declared routes and
optional template path. Existing roots and records retain their owners until an
authorized reconciliation changes them. See [workspace instructions](workspace-agents.md)
for the source/install distinction and [plan and state](plan-and-state.md) for
shared task records.
