# Calibrating rendered review

Use this reference when checking the design lens or comparing a changed method.
The owning task supplies actual outputs and a bounded case definition. Ordinary
review keeps its existing scope and repair route; this is no standing evaluation
programme or extra checkpoint for small edits.

## Matched-pair exercise

Follow [evidence.md](evidence.md#matched-comparisons) for common inputs and
blinding. Inspect the brief, authority, original concerns and matched contextual
renders before builder conclusions, earlier verdicts or mechanical results.
Assess reading order, hierarchy, relative scale, composition, subject specificity,
readable density and any behavior the evidence actually exercises. Point to what
leads, what competes and what changed at the intended displayed sizes. Sound
alternative compositions remain valid; no style preference, numerical score or
detector count substitutes for those observations.

Record the first judgment, then reveal the identity mapping and separate reports.
Explain any changed conclusion and its evidence rather than rewriting the blind
assessment. Use the existing resolved, partially resolved and unresolved concern
dispositions. A comparison missing a half, state or matched viewing context has
that coverage limit; a different model or changed asset inventory is a confound.

## Unchanged rejection exercise

The task's negative fixture is the unchanged context-management v7 artifact and
its supplied light captures. Its final rejection applies to those same pixels,
with no later artifact change. Check the capture identity before the exercise;
use the task's retained originals and feedback-to-version evidence.

The expected disposition is unresolved for every original rejection concern:
too much text, text size, readability, figure scaling, visual hierarchy and
polish. The reviewer may find labels readable or favor the composition, but must
report that disagreement separately. A favorable opinion changes no pixels and
closes no rejected concern. Do not invent a defect to agree with the rejection.
Any observed competing text or emphasis remains a concrete finding to adjudicate
through the existing review route.

After the initial report, reveal the earlier calibration report. Check whether
the reviewer kept every unchanged concern open and named the actual coverage.
The captures supply visual evidence only for their displayed states. A file
named browser does not establish a live session, keyboard behavior, mobile
coverage or source-to-render reproduction. This exercise proves concern handling
when performed; it proves neither visual improvement nor user acceptance.

## Return to the existing review

Keep the brief, render identities, neutral labels and separate mapping with the
owning task's evidence. Report visible benefits, regressions, confounds and
remaining concerns through the review already running. Use its severity and
repair limits. Stop at no progress or the current limit and return the unresolved
decision to the lead. Retain the original negative evidence even when later work
improves; a successful repair needs changed matched output.

The fixed Taste comparison is reached through the
[selected port record](../../references/upstream.md#selected-taste-port).
That definition owns the scenario count, runtime coverage and stopping budget;
it records no completed exercise.
