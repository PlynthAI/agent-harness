# Bounded project gardening

Use for requested maintenance of code and verification capability within the
existing task and tracker; add no permanent agent team or findings ledger.
Documents, feature maps included, go to docs-workspace's [docs audit](../../docs-workspace/references/docs-audit.md).

Inspect changes since the last recorded run, or the bounded PR/date range in the
assignment. Check suppression additions, repeated implementations, unwired
checks and broken launch/cleanup routes. These are leads, not defects. Establish
the requirement, reachable failure, legitimate alternatives and smallest useful
repair before changing anything. Use the harness skill for lasting lessons and
validate-implementation's maintain mode for verification drift. Prefer existing
lint/type/test tools over new rules.

Fix confirmed in-scope defects, run affected checks and get independent review.
Keep unrelated or uncertain observations as concise project findings. A missing
document is not automatically a defect. Do not manufacture rules for every
smell, repeat current evidence, or expand to a whole-repository rewrite.

For scheduled work, first inspect existing automations for overlap. Reuse one
appropriate schedule if authorized. A source/doc delta pass can be cheap; live
flows need a qualified launch, test environment, cleanup route and actual usage
allowance. Do not infer production or paid-provider permission. Keep evidence in
the existing workspace record, release disposable outputs, and report sampled
coverage honestly. Exhaustive coverage requires evidence for every mapped flow.

## Prompt to adapt for a qualified project

> Inspect the project's changes since the previous recorded gardening run. Read
> its AGENTS.md and relevant PROJECT.md guides, then use the harness skill and
> validate-implementation as needed. Investigate demonstrated verification gaps
> and actionable code defects. Fix bounded issues within the assigned scope,
> verify them and obtain independent review; open a PR and merge it through
> delivery's merge gate. Reuse unchanged evidence. Use only the qualified local/test
> commands and established resource allowance. Never infer permission for
> production, external disclosure or metered usage. Save one compact result in
> the project workspace with inspected range, actual coverage, fixes and next
> action; clean task-owned disposable output. Stay quiet when nothing meaningful
> changed. Notify on a reviewed repair, meaningful failure or genuinely
> unresolved decision, not on every run.

Fill the project, changed range and qualified commands/budget from real facts.
The prompt is a recipe, not an enabled automation or a new approval requirement.
