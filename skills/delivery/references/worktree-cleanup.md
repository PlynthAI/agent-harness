# Worktree cleanup

For this task's own merged checkout, complete [task closeout](worktree-retirement.md#close-out-the-tasks-own-checkout). The playbook below covers wider cleanup; its `wip` decision does not replace authorized reconciliation of the task's own residue.

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record the drive's free space, then run `node` [repo-inventory.mjs](../scripts/repo-inventory.mjs) `--repo <path> --sizes --chats`. It reads paths from `git worktree list`, never hand-typed, since a hand-typed path misses a worktree the runtime created under its own root. It classifies each worktree and each branch without a worktree by runtime, merge proof (ancestry, or the merged pull request's recorded head for a squash), uncommitted work, pull request state, size and the newest chat that touched it, then puts it in a bucket: `main`, `current`, `hold-uncommitted`, `hold-open-pr`, `retire` or `review`. The size and transcript scans are slow, so background them.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact. Get that set through each runtime's liveness route in [worktree-retirement.md](worktree-retirement.md#check-liveness-per-runtime-before-removal) and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. For every `verify-recent-chat` row, or anything you doubt, fan read-only subagents out to read the transcripts and report whether the chat is pinned or ongoing and which worktrees it touches (transcripts are bulk; keep them out of your own context). A pinned chat can spawn repro and sketch trees into sibling worktrees via background subagents, and those are in use even when their names never hit the sidebar.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. `.state/` at the worktree root is the task's ignored scratch (the team lead's state file, the reviewer's findings) and goes with the worktree, so look inside it and copy anything worth keeping to the project's artifacts first. Clean and merged and not-in-use proceeds within the cleanup request. `wip` and in-use pause.
5. Retire the confirmed set with `node` [retire-worktree.mjs](../scripts/retire-worktree.mjs) `<worktree-path>...`, which carries the method in [worktree-retirement.md](worktree-retirement.md): read the plan it prints, then rerun with `--apply`. It unlinks links and junctions first, removes from outside the candidate without force, verifies the directory, any residue folder and the registration gone, deletes the task branch and its remote only at the proven merged tip, preserves the canonical checkout for its owner (new worktrees use the supported launcher with a current base), releases the checkout's code-graph index and reports free space before and after. A refusal is a result: it names the reason, and nothing is forced past it. `--branch <name>` retires a merged branch whose worktree is already gone. Re-list with the inventory afterwards.
6. Other reclaimers. On macOS, simulators are usually the next-biggest win: `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport`, the runtime's own state and snapshot roots, package caches (pnpm, uv, brew, yarn). Clear only caches the user has not said to keep; [storage lifecycle](../../keep-codex-fast/references/storage-lifecycle.md) maps the common roots and their retention.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** free space before and after with space reclaimed, the worktrees pruned, a one-line reason for each held back (in-use by which chat, or uncommitted work), and each background command this task started (server, watcher, browser) with its stop command, stopped unless handed over.
