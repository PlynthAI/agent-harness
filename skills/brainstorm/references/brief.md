# The brief

The closing output of a brainstorm: short, honest about what is not settled, and
not an approval.

## Shape

| Part | What it carries |
|---|---|
| Outcome | What the discussion established, in the person's own terms |
| Decisions | What the person actually decided, and what it rules out |
| Unresolved questions | What is still open, why, and what would settle it |
| Non-goals | What this deliberately does not cover |

Scale it to the discussion. A few lines is a complete brief for a small idea; a
complicated question may need a short page. Never pad it.

## A small software idea

```text
Outcome: the settings page reads the same preferences file the command line writes.
Decisions: keep one file, settings.toml, and the command line keeps writing it.
Unresolved questions: whether the page reloads live - needs an answer before building.
Non-goals: migrating existing preference files, and adding new preferences.
```

## A question with no code in it

```text
Outcome: the launch event needs a venue decision before invitations go out.
Decisions: the budget is 4,000 and the date is fixed.
Unresolved questions: the venue - the studio fits the guest list but not the catering; who signs the contract.
Non-goals: the after-party, and travel for out-of-town guests.
```

## What the brief is not

- It is not an approval. Never label it accepted or approved.
- It is not a plan, and it does not require one.
- It is not a decision record. A durable decision can be offered one separately,
  and only when it is warranted.
- It records only what the person decided. Everything else stays under Unresolved
  questions.
